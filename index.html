What this fixes

Old bridge: one GitHub commit per file, with a stale-SHA propagation bug causing errors such as “is at SHA A but expected SHA B”.

V5.2: no per-file update SHA is used. It reads the current branch once, builds one new Git tree, creates one commit, then advances the branch with a fast-forward-only update.

Important: this bridge does not delete unrelated files. It also does not overwrite the project history to “clean up” the earlier partial commits.
