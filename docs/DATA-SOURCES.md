# Presentation, image links, music and retail provenance

## Working paths in this branch

- `/tools/presentation-creator`: a topic (and optional user notes) is sent to `/api/presentation`. The server searches Wikipedia, optionally Brave web search if `BRAVE_SEARCH_API_KEY` is configured, then makes a downloadable, editable `.pptx` with PptxGenJS. AI Mode's “make a PPT about …” Run and chat paths execute this same tool rather than describing a future chain. Facts without user notes are **attributed source snippets**, not independently fact-checked AI research. The deck contains a cover, source-derived or user-note slides, and links to source pages. An outage with no notes fails rather than inventing content. Attached files/YouTube are **not** ingested into decks; the agent says so. Search breadth is Wikipedia-only by default, not all of the Internet. No image bytes are stored or embedded.
- `/tools/reviewed-image-link-directory`: Openverse candidate discovery uses `mature=false`, Wikimedia Commons source and CC0/CC BY/CC BY-SA license restrictions. `node scripts/image-links-runner.mjs` stores **only link and license metadata** in `data/image-links/candidates.json`, not image files. Candidate images are *never* served publicly. A human must inspect the linked Commons page for age safety, provenance and license before running `node scripts/approve-image-link.mjs --id <candidate-id> --ack-reviewed`; only the approved metadata goes to the mirrored public index. No automatic 18+ detection is perfect: do not approve uncertain content. Openverse may omit or mislabel licensing or maturity; manually verify. The branch trial discovered **48 unreviewed link candidates** from six narrow queries; until manual review there are **zero publicly indexed images**. The deck includes only approved links as references, not the image itself.
- Worldwide music is **not Trivandrum music places**. `/api/open-music` searches open MusicBrainz recording metadata on demand (one request per second per server instance, in-memory short cache), and shows an *unverified search link* into Spotify rather than asserting an ID match. `scripts/open-music-runner.mjs` can collect a bounded CC0 snapshot after successful queries; it does **not** collect Spotify catalogue records. The old public-embed-token Spotify scraper and bulk POST ingest are disabled. The historical ten-track scraped snapshot has been removed from this branch; the latest successful branch MusicBrainz run published **36 sampled CC0 recordings**. This is a tiny sample, not worldwide coverage. MusicBrainz is itself not a complete Spotify catalogue. MusicBrainz API rate limit and terms still apply.
- Nationwide products: zero verified listings currently published. `scripts/import-authorized-products.mjs` accepts at most 1000 valid INR listings per feed batch, with seller, product URL, timestamp and permission evidence, after the operator explicitly sets `AUTHORIZED_PRODUCT_FEED=1`. Feed JSON shape: `{ "authorization":"operator-confirmed-licensed-feed", "permissionEvidence":"https://...", "retailerDomain":"flipkart.com", "products":[{"id":"...","title":"...","seller":"...","category":"...","price":999,"currency":"INR","verifiedAt":"2026-09-26T00:00:00Z","productUrl":"https://www.flipkart.com/..."}] }`. The script validates structure/domain and records provenance but **cannot independently verify legal authorization**; the operator must obtain permission before import. Do not commit credentials or a raw restricted feed. Free storage/compute do not confer permission to scrape Flipkart/Amazon or provide a complete detailed nationwide catalogue. Official affiliate/retailer feeds and refresh rights are prerequisites.
- Trivandrum OSM shops and music **places** remain a separate geographic dataset with OSM/ODbL attribution. They are not the worldwide music catalogue or nationwide retail inventory.

## Operations and limits

`npm test` includes PPTX ZIP creation, refusal/metadata review gate, authorized-feed validation, open-music and Vercel bundle tracing. Tests mock upstream calls; they do not prove external providers are reachable in production. Branch collection can refresh bounded MusicBrainz metadata and OSM cells, and stage **unreviewed** image-link candidates, but no GitHub action auto-approves images or acquires product-feed rights. Old counts in historical run reports describe *trials*, not the current music snapshot. Serverless rate limiting is instance-local and not a distributed abuse-control system. A new rollout requires review/merge and deployment; branch changes alone are not live production.
